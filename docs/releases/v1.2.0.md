# RTX HDR Image Studio v1.2.0

This release adds large-image processing, a focused-image GPU memory estimate, and improved preview anti-aliasing.

## Highlights

- Raise the application input limit to **943,718,400 pixels** (30720 × 30720). Use NVIDIA's native C API to bypass the Python binding's large-image input-transfer failure.
- Reduce large-image memory pressure with bounded color conversion/readback, mapped scratch buffers, resource checks before decoding, and exact mapped FP16 JXR verification.
- Show estimated GPU memory demand at the previewer's upper right. The scale remains the selected GPU's dedicated VRAM capacity, with green/yellow/red pressure colors and a separate estimate of shared-memory overflow. Only the focused image is counted.
- Keep processing serial, including across application instances in the same Windows session, and clean interrupted scratch buffers after the worker stops.
- Improve SDR/HDR previews with Lanczos-3 and area prefiltering. Background final-size SDR caches avoid repeated filtering when dragging the split divider or switching views.
- Set saturation to **150** for **HDR400, HDR600, HDR1000, and HDR1000 Highlight**. NVIDIA default remains unchanged.
- Simplify README usage text and refresh its synthetic interface screenshot.

## Validation and limits

Local validation passed 123 CPU/UI tests, 5 real NVIDIA tests, and 2 Windows native HDR tests, along with lint/format, isolated package builds and package-content checks. Real 100MP and 400MP PNG inputs completed preview creation and original-size JXR export with exact decoded-sample verification on an RTX 3070 Ti Laptop (8GiB), driver 621.01. Full-resolution JXR output remains unchanged by preview filtering.

**943.72MP is an application ceiling, not a guarantee of available resources or support for every shape/codec.** The SDK-only test processed that size, but the complete application could not export it within the current system commit reserve. The application now rejects insufficient-resource requests before full decoding and large GPU allocations. Large images can require tens of GiB of RAM and scratch space. Shared-memory estimates are approximate; Windows controls actual residency and other applications affect availability.

Preview caches remain bounded by 3840 × 2160. Inference and export preserve source dimensions. Codec limits, upstream SDK/driver support, and viewer/Windows HDR behavior still apply. The application does not change system display settings. See [testing evidence](https://github.com/TeddyWEinzbern/rtx-hdr-image-studio/blob/main/docs/testing.md) for measurements and their scope; automated CI does not establish physical HDR appearance.
