# Architecture

The package uses the `src/` layout so tests do not accidentally import an unrelated checkout. Installation uses declarative `pyproject.toml` metadata; there is no custom setup code or dependency installer.

| Module | Responsibility |
| --- | --- |
| `settings.py` | Immutable settings; strict validation and JSON boundary |
| `color.py` | Transfer functions, PQ decoding, primaries conversion, tone mapping, statistics |
| `image_io.py` | Supported-decoder allow-list, EXIF/ICC/alpha/16-bit input handling and reduced preview caches |
| `decoder.py` | Killable helper process that decodes source images for the GUI |
| `job_cache.py` | Ownership and cleanup of job cache directories and export staging files |
| `engine.py`, `native_vfx.py` | Delayed GPU imports, owned RGBA8/RGB10A2 buffers and NVIDIA C API synchronization |
| `resources.py` | Pixel/resource policy, mapped scratch buffers, process mutex and GPU capacity lookup |
| `export.py` | Exact FP16 verification and collision-safe publication |
| `pipeline.py` | Per-file orchestration; engine injection for CPU tests; batch failure isolation |
| `worker.py` | Subprocess JSON protocol and top-level failure reporting |
| `runtime.py` | User-data directories and discovery of already-installed CUDA DLLs |
| `graphics/` | Read-only Windows display detection and native D3D11 FP16 presentation |
| `ui/` | English Qt window, parameter controls, comparison canvas, subprocess lifecycle; `ui/composition.py` describes split frames as GPU copies |

The GUI never performs inference on its event-loop thread. `JobRunner` starts the same Python environment as a subprocess (`python -P`, so the job directory is never on `sys.path`) and passes a JSON request file. Structured progress uses the `@HDRJSON:` prefix; all other output goes to a local job log. The GUI finishes a job only after the thread has exited. Cancellation terminates and reaps the worker; window shutdown waits for cleanup. Each job has a random 32-hex identifier created by the GUI: it names the job's cache directory and the export staging files (`.rtx-hdr-<id>-*`). After a worker is reaped, the parent removes that job's unpublished staging files, which a terminated worker cannot clean up itself; files of other jobs and published exports never match. The window deletes a job directory once no in-memory result references it (the latest job is kept for "Open job log"), deletes all of its session's directories on exit, and removes crash leftovers idle for more than 24 hours at start-up. Job and decoder directories record their GUI owner PID; stale cleanup preserves directories whose owner is still running, even after prolonged inactivity.

The pipeline accepts an `HdrEngine` protocol and factory, allowing deterministic CPU-only tests without pretending to validate NVIDIA inference. The native adapter calls the installed VFX 1.3.0 C API directly. Bounded input strips retain the existing color math and nearest-integer RGBA8 quantization, bypassing the Python binding's large planar-input transfer. Each image receives one full-size inference call. The input chain (linearization, exposure, gamma and quantization) is a per-channel function of an 8-bit code, so it runs as a 256-entry lookup table that is byte-identical to the float formula. Packed output is read into scratch storage, then the effect and GPU buffers are released before float32 scRGB conversion; image statistics are accumulated in the same strip loop. Because the PQ table is finite and the output is bounded (|scRGB| < 300), export skips its full-size range pre-scan for this engine. A native failure ends the worker rather than reusing a potentially damaged CUDA context; cleanup does not synchronize a failed context again, so the original NVIDIA error (with the file name) is what the interface reports.

The 943,718,400-pixel input policy is shared by metadata queries and decoders. Pillow identifies files by content, so identification is restricted to the PNG, JPEG (including MPO), WebP, BMP and TIFF plug-ins: a renamed EPS, PSD, FITS or PDF is rejected instead of reaching Ghostscript or another decoder. Unsigned 16-bit grayscale is mapped from its full 0–65535 range (`round(v × 255 / 65535)`); signed-integer and floating-point modes are rejected rather than clipped. Header queries never decode PNG IDAT just to look for EXIF. JPEG drafts and bounded thumbnails reduce GUI decode costs. The GUI decodes source files in two long-lived helper processes (`decoder.py`, one for previews and one for metadata) rather than in its own process: a native decoder crash is reported as an error instead of closing the window, a long decode of an image the user has left is abandoned after one second, and closing the window kills the helpers so the process exits without waiting for an uninterruptible decode. Helper scratch storage lives in an owned cache directory that is removed when the helper stops. Full decoding still applies to formats without reduced-size decoding. Processing uses per-image mapped scratch buffers above 64MiB, bounded color/statistics operations, separable large-image resampling, and tone mapping at preview resolution. JXR encoding retains the codec's full compressed blob, but RGBA input and exact decoded verification can use mapped storage. RAM/commit and scratch-disk checks precede large allocations. Normal cleanup closes mappings before deleting them; the parent removes scratch directories after terminated workers are reaped.

The GUI prevents duplicate jobs; a named Windows mutex prevents simultaneous processing by separate application instances in the same session. Batch items remain serial. The header's memory widget estimates only the focused image using the empirical native model (247MiB + 32.068 bytes/pixel); it does not sum queued or completed images. Capacity is queried off the UI thread by matching the CUDA ordinal's PCI bus ID to NVML, without initializing a GUI CUDA context. The bar's range remains dedicated VRAM capacity, with green/yellow/red thresholds at 80/90 percent and separate shared-memory overflow text. This is a planning estimate, not live residency telemetry or a guarantee of capacity on every card.

Native preview uses a separate opaque child HWND. FP16 linear scRGB values are presented through a D3D11 flip-model swap chain. Each prepared before/after pair is uploaded once to two GPU textures; every repaint (including each mouse move while dragging the divider) is a full-height `CopyResource`/`CopySubresourceRegion` per side plus a small `UpdateSubresource` for the divider and, in full screen, the exit hint region. The CPU composition in `ui/composition.py` is the reference for exactly the same plan. The CPU prepares scaled comparison frames in linear light; export never uses those scaled buffers. A display-state timer distinguishes HDR from SDR/ACM and adjusts the original side to the system SDR white level. Rendering failures fall back to the standard Qt SDR preview.

`LatestTask` runs widget-free work in bounded background pools. Each task retains one running request and only its newest pending replacement, with generation checks before publishing results on the GUI thread. Cached PNG decoding uses QImage; HDR loading/validation, float32 original linearization, and full-frame resizing happen in background jobs. The GUI commits QPixmaps and presents already prepared frames. Data and frame jobs are cancelled logically on replacement or shutdown, so stale work cannot reactivate an old image or a closed window.

Preview resampling uses Lanczos-3 with a scale-aware kernel and an integer area prefilter (`reducing_gap=3.0`) for large reductions. The large-image path filters full-width horizontal strips and full-height vertical strips, avoiding seams and giant float planes. Native HDR filters in linear light without clamping negative or above-one values. SDR additionally prepares image pairs at the final physical viewport size on a background task: painting and divider/view changes reuse these pixels. The key includes source images, physical viewport dimensions, scaling mode and margin, but excludes divider position and selected comparison mode. Fill prepares only the visible source region. Unscaled images bypass filtering; pending results temporarily use Qt's smooth transform instead of nearest-neighbor rendering.

`PreviewDevice` initializes a D3D11 device in a separate background pool, then transfers exclusive immediate-context use to the GUI thread. Main and full-screen surfaces share those device resources, while owning separate HWND swap chains. Updating image content suspends a surface without destroying its presenter. Closing surfaces releases swap chains first; closing their owner releases the shared device after all surfaces and preview tasks are stopped. Pending initialization discarded after shutdown releases its own unused resources. DirectX failures keep their HRESULT. When `Present` or `ResizeBuffers` reports device removal, reset, hang or an internal driver error, the surface leaves its paint handler and asks `PreviewDevice` to recover: every surface releases its swap chain and textures, the shared device is released and recreated in the background, and surfaces show their prepared frames again. More than three losses within 60 seconds keeps the SDR fallback with an explanation instead of looping. Other rendering errors fall back to SDR as before.

Progress messages include the source path. The window tracks the current processing source independently of the selected source. Only the active source is forced to Original, barred from mode/full-screen changes, and removed from full-screen viewing. The queue remains usable during a batch; completed and not-yet-processed sources retain their normal controls. Terminal file events and job cancellation/failure release that restriction.

Preview caches fit inside 3840 × 2160 without upscaling. The full-screen button and image double-click open a separate comparison canvas with a snapshot of the current images, mode, and divider position. A centered exit hint is painted into the SDR canvas or alpha-blended into the FP16 HDR frame in linear light at the display's SDR white level. This avoids stacking a raster widget above the native child HWND or applying SDR opacity effects to the HDR image. A one-shot timer hides the hint after three seconds and signals the owner to suppress it for the rest of the current run. Closing early leaves the hint eligible on the next entry. The owner keeps this state in memory only; a new application run resets it. Mouse activity does not restart it. Image double-click, Esc, window/application deactivation, and owner shutdown close the viewer and release its timers and native renderer. Generated-view buttons are enabled only when the selected image has a processed preview.

Exports preserve source dimensions and pixel format policy. Filename collision handling and same-directory staging avoid partial or overwritten output. Metadata sidecars are best-effort and do not invalidate an already successful JXR export. Logs/caches live outside the installed package and are never installed into the repository.

Full-screen Fill uses centered aspect-preserving cover geometry shared by SDR and HDR. HDR frame preparation resizes only the visible source crop, avoiding oversized intermediate buffers for extreme aspect ratios. Divider dragging is clamped to the visible image area. Successful file events mark that source for a one-time switch to Split view after its new preview loads; completion of another source leaves the selected view untouched. Starting another processing pass discards any pending switch for that source.

Qt SDR drawing, native HDR composition, and image hit testing share physical-pixel placement calculations. Full-screen scaling can fit with aspect ratio, stretch, or retain the preview's pixel dimensions; actual-size images that exceed either screen dimension fall back to fit. This avoids treating Qt logical pixels as image pixels at high display scaling factors. Preview buttons reflect the effective visible mode, including Original when no generated result is available.

In full-screen Split view, a left-button drag starting inside the image updates the viewer's divider without changing the main canvas or restarting the hint timer. The divider is constrained to the displayed image, including letterboxed actual-size previews. The native child forwards press, move, release, and double-click events to the same controller used by the SDR canvas.

Dropdowns retain Qt's selection handling and calculate a final popup rectangle before showing the list. The opening call temporarily disables Qt's combo animation and paints only after final placement, then restores the previous application animation flag. Available screen space determines whether the list opens below or above, and constrains its width and height if necessary. The preview status combines HDR/SDR readiness with the selected result's image peak; settings mismatch appends (Outdated) and applies a red text style. There is no separate image-peak panel.
